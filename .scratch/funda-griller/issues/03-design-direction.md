# 03: Design direction

**What to build:** The design foundation for all four screens (Buyer Profile form, Listings list, Case detail, Verdict page), produced with the impeccable skill: first `init` to capture durable product context, then `shape` for each screen. The surface is an Operate-mode tool, so scanability and trustworthy provenance matter more than decoration. Output is decisions and briefs, not production UI.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Product context (users, mode, tone, constraints) is captured in PRODUCT.md
- [ ] A shaped brief exists for each of the four screens covering information architecture, key states (empty, loading, error, Stale) and the main interactions
- [ ] The visual direction is chosen and written down: type, colour, density, and how Base UI primitives will be themed
- [ ] The brief shows how provenance (Listing, Source, Observation, Finding), Stale badges, Flags (pro, con, risk) and the four Verdict tiers are distinguished visually, including accessible non-colour cues
- [ ] The brief shows how a Case with dozens of facts stays scannable, and how the comparison list reads at a glance
- [ ] Any unresolved screen is settled with a throwaway prototype of UI variants, and the chosen variant is recorded
- [ ] Desktop-first, with the briefs stating what changes at narrow widths
